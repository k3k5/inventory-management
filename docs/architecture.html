Factory Inventory Management System

Architecture overview of a full-stack workshop demo: Vue 3 single-page app, FastAPI REST backend, and in-memory data loaded from JSON files.

Executive summary

What the system is and how it is built.

  • Purpose: inventory tracking, order management, demand forecasting, backlog monitoring and spending analytics for factory operations.
  • Shape: a two-tier web app. The browser SPA (port 3000) calls a stateless REST API (port 8001) directly via CORS.
  • Persistence: none. JSON files are read once at server start and held in memory; there is no database, authentication or write path that survives a restart.
  • Maturity: demo / workshop quality, intended for local use (see Observations).

Data flow

How a filter change on the dashboard turns into updated numbers.

Request lifecycle

  1. User changes one of four filters (time period, warehouse, category, order status) in FilterBar.
  2. State lives in the shared useFilters composable; the view reads it via getCurrentFilters().
  3. api.js builds a query string, skipping any value equal to all, and calls the API with Axios.
  4. FastAPI route receives optional warehouse, category, status, month params.
  5. apply_filters and filter_by_month narrow the in-memory lists (month accepts 2025-01 or quarter form).
  6. Result is validated by a Pydantic response_model (or aggregated, e.g. dashboard summary) and returned as JSON.
  7. The view stores raw results in refs; computed properties derive chart series and KPIs, and Vue re-renders.

Observations

Findings from reading the code; worth confirming before relying on them.

  • Gap api.js calls /tasks and /purchase-orders (GET/POST/PATCH/DELETE), but main.py defines no such routes. These client calls would return 404 until the endpoints are added. CreatePurchaseOrderRequest exists as a model but is unused by any route.
  • Security No authentication, CORS allows all origins, API base URL is hard-coded to http://localhost:8001. Acceptable for a local demo only.
  • Scale All filtering happens in Python over in-memory lists; fine for the current data size, not for production volumes.
  • Design Clean separation: one API client, shared filter composable, uniform "all means no filter" convention across client and server.
  • Docs The start.sh stop hint refers to ./stop.sh, but the script lives in scripts/.
